# 開発ルール

## 1. コーディング方針

- すべての関数・メソッドに型ヒントをつける
- クラス / 関数でロジックを分割し、巨大な script を避ける
- Docstring は日本語で「何をするか」「引数 / 戻り値」を明記
- コードコメントには "Why not" を書く（採用しなかった選択肢の理由）

## 2. テスト方針

- フレームワーク: pytest
- `tests/` 配下にファイルを作成
- テストコードには "What を検証しているか" をコメントで書く

例:

    """ノートを1件挿入して、同じ内容で取得できることを確認するテスト。"""
