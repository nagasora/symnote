# SymNote 有料化の方針（料金・課金・リリースまでの道筋）

最終更新: 2026-10-17 ／ 状態: 方針合意（数値は β で検証して見直す）

## 1. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 提供形態 | **Web アプリ（PWA）** | iPhone・Android・PC を 1 つのコードで賄える。ホーム画面に追加すればアプリのように使える。ストア審査が要らない |
| 決済 | **Stripe**（Checkout ＋ Customer Portal ＋ Webhook） | 手数料 3.6%。アプリ内課金（26%、小規模 15%）やリンクアウト（15%、小規模 10% ＋決済手数料）より大幅に安い |
| 料金モデル | **フリーミアム** | 無料で使い始めて、AI と連携機能が欲しくなったら有料へ。ユーザーを増やしやすい |
| 有料プラン | **¥980／月、¥9,800／年**（年払いは約 2 か月分お得） | 個人向け生産性アプリの相場。Addness（チーム向け $39／人／月）より大幅に安く、個人に絞った差別化 |
| 無料体験 | 有料プランを **14 日間** 無料で試せる（カード登録あり） | 有料機能の価値を体験してから判断してもらう |

## 2. プランの中身

| | Free | Pro（¥980／月） |
|---|---|---|
| タスク・ゴール・メモ・繰り返し・クエスト | 無制限 | 無制限 |
| マインドマップ（手動） | ○ | ○ |
| AI 呼び出し（秘書・分解・マインドマップ生成・抽出など） | **1 日 10 回・月 100 回** | **1 日 100 回・月 1,500 回** |
| Google カレンダー自動同期・AI 時間割 | — | ○ |
| ChatGPT / Claude 連携（MCP）・ChatGPT 履歴からの ToDo 抽出 | — | ○ |
| Gmail からの ToDo 抽出 | — | 後日（§5 参照） |

AI が使えない・上限に達したときも、手動の操作は全プランでそのまま使える（既存の設計を維持）。

## 3. 採算（1 ユーザーあたりの原価）

AI モデル `gemini-3.1-flash-lite`：入力 $0.25／100 万トークン、出力 $1.50／100 万トークン。
1 回あたり入力 約 3,000・出力 約 1,000 トークンと見積もると **約 $0.00225 ≒ ¥0.35／回**（$1 = ¥150）。

| | 上限いっぱいまで使った場合の AI 原価／月 | 売上（手数料 3.6% 差引） | 粗利 |
|---|---|---|---|
| Free | 100 回 × ¥0.35 ≒ ¥35 | ¥0 | −¥35 |
| Pro | 1,500 回 × ¥0.35 ≒ ¥525 | ¥945 | **＋¥420 以上**（平均的な利用なら ＋¥800 前後） |

- 月の上限を設けるのは、日の上限（100 回）を毎日使い切られると ¥1,050 になり赤字になるため。
- 固定費（サーバー・ドメイン・バックアップ）は月 ¥3,000〜5,000 を想定 → **有料 10 人前後で黒字**。
- モデルを変えるときは単価を測り直してこの表と上限を更新する。

## 4. 課金の仕組み（実装方針）

1. 料金ページ → Stripe Checkout（カード／Apple Pay／Google Pay）。14 日の無料体験は Checkout の trial で付ける。
2. Stripe の Webhook（`checkout.session.completed`・`customer.subscription.updated/deleted`・`invoice.payment_failed`）を受けて、利用者ごとの `plan` と `plan_until` を DB に保存する。Webhook は署名を必ず検証する。
3. 解約・カード変更・領収書は Stripe Customer Portal に任せる（自前の画面を作らない）。
4. AI の上限は既存の `core/usage_limit.py` を利用者のプランから決めるよう拡張する（`set_usage_scope` に利用者 ID を入れる仕組みは実装済み）。
5. 支払い失敗時は 7 日の猶予の後に Free に戻す。データは消さない。

## 5. 有料リリースまでの道筋

現在の SymNote は「自分 1 人・自分の Mac」前提（ログインなし、DB 1 つ、Google 連携もアプリ全体で 1 つ）。
有料で他人に使ってもらうには以下が必要。

| 段階 | 内容 | 目安 |
|---|---|---|
| 0. 実機テスト（自分） | `scripts/start_test.sh --remote` で外出先のスマホから試す | **済** |
| 1. マルチユーザー化 | ログイン（Google ログイン or メールのリンク）、利用者ごとのデータ分離（利用者ごとに SQLite ファイルを分ける案が既存コードを活かしやすい）、Google のトークンを keyring から暗号化した DB 保存へ | 大 |
| 2. 課金 | §4 の Stripe 連携、プランと AI 上限の連動、料金ページ | 中 |
| 3. 法務 | 利用規約・プライバシーポリシー・特定商取引法に基づく表記（個人の場合は住所・電話番号の扱いに注意） | 小 |
| 4. Google の審査 | カレンダー（機密スコープ）の OAuth 審査。**Gmail 読み取りは制限付きスコープで、毎年の有料セキュリティ評価（CASA）が必要なため初回リリースから外す** | 数週間 |
| 5. 本番環境 | 常時稼働のサーバー・独自ドメイン・HTTPS・毎日のバックアップ。Streamlit は利用者ごとに接続を保持して重いため、β は Streamlit、本格公開は `docs/redesign/PLAN.md` の FastAPI＋React へ | 中〜大 |
| 6. 招待制 β → 一般公開 | 少人数で支払い意欲と原価を検証し、§1〜3 の数値を見直す | — |

## 6. 見直す条件

- β で有料転換率が 3% を大きく下回る → 無料枠と Pro の差（どの機能を有料にするか）を見直す。
- 平均 AI 原価が ¥300／人／月を超える → 上限またはモデルを見直す。
- iPhone アプリとしてストアに出す要望が強くなる → 「Web 先行・ストア版は Web 決済へのリンクアウト」を検討する。
